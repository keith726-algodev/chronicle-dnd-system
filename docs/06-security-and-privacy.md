# Security and privacy checklist

The riskiest security issue in Chronicle is the possibility of exposing database credentials or other sensitive configuration when publishing the project to a public GitHub repository. Since the client connects to an Express API backed by PostgreSQL, I need to keep actual credentials in environment variables, exclude `.env` files from Git, and use placeholder values in `.env.example`. I also need to ensure that database queries are parameterised, server-side inputs are validated, and CORS only allows the intended frontend origins. For privacy, the campaign and seed data should be fictional, with no real classmates’ names, contact details, or other personal information. I knowingly accepted that the current prototype has limited account-level privacy controls because it is designed around campaign content rather than individual user accounts; if accounts or shared personal data are introduced later, authentication and data-ownership protections will need to be added.
